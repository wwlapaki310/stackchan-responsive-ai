# デモ動画の台本と撮影メモ

長さの目安は約75秒（1〜3分の枠の中）。動画は、**実機の映像を主役**にして、ダッシュボードとシミュレーション図を重ねる。字幕を入れ、音声のナレーションは足さなくてよい（本体の声が主役）。

## 3つの見せ方の軸

| 軸 | 動画で見せるもの |
|---|---|
| ロボティクス工学 | 首の追従制御（比例→積分）、閉ループのシミュレーション図、追従方式の切り替え（顔検出／動き） |
| OSS（貢献・活用） | pico（MIT）・Open JTalk・M5Stack BSPを使用。MITで公開。M5Stack公式 Issue #70（会話中の視覚追従）への報告材料 |
| AI処理 | 本体での顔検出、本体での音量認識、認識した状況を文章にしてクラウドLLM（Sarashina）へ送る |

## 台本

| 時間 | 画面 | 字幕（案） | 本体の声・動き |
|---|---|---|---|
| 0:00–0:05 | タイトル | 「考えていても、そばにいるStack-chan」 | |
| 0:05–0:15 | 本体のみ（誰もいない） | 「誰もいないとき: 自分で見回す」 | 「起動しました。こんにちは。」首が左右へ |
| 0:15–0:25 | 本体＋ダッシュボード（首の角度） | 「顔を見つけて追う（本体上の顔検出）」 | 「あ、人を見つけました。」首が向く |
| 0:25–0:45 | 本体＋ダッシュボード（青い帯） | 「回答を待つ間も止まらない」「状況を言葉にして、クラウドLLMへ」 | 「ちょっと考えますね。」「えーっと。」触ると「くすぐったいです。」→ 回答が字幕に出る |
| 0:45–0:52 | 本体 | 「音にも反応（音量だけ。録音しない）」 | 首が止まったところで拍手 →「はい？」 |
| 0:52–1:02 | 本体（通信を遅くした状態） | 「通信が遅れても同じ（故障注入で再現）」 | 15秒待つ間も追従・相づち → 「時間切れ」と言って戻る |
| 1:02–1:10 | シミュレーション図（`docs/sim/track_sim.png`） | 「追従制御の比較（シミュレーション）: 積分で定常誤差が消える」 | |
| 1:10–1:15 | 構成図＋「MIT / pico / Open JTalk / Issue #70」 | 「公開: MIT。公式への報告材料に」 | |

**注意（正直さ）**
- 1:02 の通信の遅れは、**試験用の故障注入**で作る。字幕で必ず「再現」と書く。実際の応答は約0.6秒と短い。
- シミュレーションは、画角60°とサーボ速度90°/sを**仮定**した計算。実機の性能ではないと、字幕に書く。
- 顔検出の検出率は低い（動画では、正面から見せる）。数字を出すなら、ログから出す。

## 撮影の手順

1. 本体を机の上に置き、カメラが顔の高さで正面を向くようにする。部屋は明るくする。
2. 画面の録画: PCのブラウザでダッシュボードを開き（URLの`?t=`は映さない）、本体を別カメラ（スマホ）で撮る。あとで並べる。
3. 通し撮りは、0:05〜0:52 を1回で。失敗したら撮り直す（顔検出が途切れやすいので、数回撮る）。
4. 通信が遅い場面: ボタンはない。PowerShellで `Invoke-RestMethod -Method Post "http://stackchan.local/opt?n=fault&v=3&t=<トークン>"` を実行して「ハング」にし、質問する。終わったら `v=0` で必ず元に戻す。
5. 編集: 字幕を入れ、本体の声は残す。BGMは、権利のあるものか、なしにする。
6. 書き出して、YouTube（限定公開でよいか、課題の指示を確認）に上げる。

## 撮影前のチェック

- [ ] `secrets.h` は、動画に映らないところで扱う。URLのトークンを隠す。
- [ ] Wi-Fiが安定している（-40dBm前後）。
- [ ] 読み上げ（OpenAI）はオフのまま（既定）。
- [ ] 本体を再起動して、挨拶から質問まで通ることを、先に1回確認する。

## 言えること・言えないこと

言える（根拠あり）:
- 実機で、顔検出→挨拶→自分から質問→回答待ちの間も追従・相づち→回答の字幕、が動いた（ダッシュボードの記録、2026-10-30）。
- 通信の失敗（誤キー、到達不能、ハング）から、本体が回復した（`tools/fault_check.py`）。
- 追従制御の比較は、シミュレーションで、積分制御が定常誤差を除くことを示した。

言えない:
- 顔検出の精度が高い。自然さや愛着。待ち時間が短くなった（比較していない）。
- 画像・音声の中身をAIが理解している。本体は、顔の有無・時間・向き・音の大小だけを文章にして送っている。

## Gazebo/ROSについて

今回は使わない。Gazebo用のStack-chanのモデルがなく、環境の構築と検証が、提出までの時間に収まらないため。代わりに、Pythonで閉ループの追従制御を計算した（`tools/track_sim.py`）。動画では、その図を見せる。ROS/Gazeboは、今後の課題として書く。
