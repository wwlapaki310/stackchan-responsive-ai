# デモ動画の台本と撮影メモ

長さの目安は約75〜90秒（1〜3分の枠の中）。**実機の映像を主役**にして、ダッシュボードとシミュレーション図を重ねる。字幕を入れ、ナレーションは足さなくてよい（本体の声が主役）。

## 3つの見せ方の軸

| 軸 | 動画で見せるもの |
|---|---|
| ロボティクス工学 | 首の追従制御（比例→積分）、閉ループのシミュレーション図、追従方式の切り替え（顔検出／動き） |
| OSS（貢献・活用） | pico（MIT）・Open JTalk・M5Stack BSPを使用。MITで公開。M5Stack公式 Issue #70（会話中の視覚追従）への報告材料 |
| AI処理 | 本体の顔検出・音量認識（本体のみで動く）と、分からないことだけクラウドへ送る振り分け。文章はSarashina、画像の解釈と読み上げはGemini |

### 場面ごとの注意
- **場面1**: 本体の字幕に出る回答を、スマホ（左画面）で映す。ダッシュボードの「豆知識」の位置が、右画面で見えること。
- **場面2**: 首を振っている間は、拍手を試さない（マイクが効かない）。
- **場面3**: 検出が外れることがある。外れたら、顔を少し動かして、もう一度見せる。3秒追従で、自動の質問が出ない場合は、次のテイクにする。
- **場面4**: 「判断」は、押すたびに、本体のみ→「見て」のときだけ→常にGemini→本体のみ、と回る。**1回だけ押す**。「常にGemini」まで進めない。「読み上げ」を押さないと、声では読まない。
- **場面5**: 「見て」を押したら、あなたは動かず、手に持った物を見せ続ける。待ち時間は、5〜15秒でばらつく。失敗（エラー、時間切れ）したら、30秒あけて、撮り直す。
- **場面6**: 場面5の読み上げが終わって、2〜3秒たってから叩く（声の再生中は、マイクが止まっている）。
- **終わったら**: **「判断」を押して「本体のみ」に戻し（2回押す）、「読み上げ」を押してオフにする。**

**注意（正直さ）**
- 「見て」は、**画像1枚を、本体からGoogleのGemini APIへ送る**。既定はオフで、「判断」を切り替えたときだけ動く。字幕に「画像をクラウドへ送信」と書く。
- 応答は5〜15秒でばらつく（実機で十数回）。読み上げまでの合計は、10〜20秒になることがある。時間切れで失敗する回もある。**うまくいった回を撮る。編集で詰める場合は字幕に「（編集で短縮）」と書く。**
- Geminiの無料枠には回数制限があり、読み上げは「429」で失敗することがある（そのときは字幕だけ出る）。撮影は、続けて何度も呼ばない。
- シミュレーションは、画角60°とサーボ速度90°/sを**仮定**した計算。実機の性能ではないと字幕に書く。
- 顔検出の検出率は低い（動画では、正面から見せる）。数字を出すなら、ログから出す。

## 撮影前の準備（今夜）

1. `powershell -File tools/gen_secrets.ps1`（`GEMINI_API_KEY`、`SARASHINA_API_KEY`、Wi-Fiが環境変数に入っていること）。
2. ビルドして書き込み（READMEの手順）。
3. 本体を机に置く。カメラが顔の高さで正面を向くようにする。部屋は明るく。
4. PCのブラウザでダッシュボードを開く（`http://stackchan.local/?t=<トークン>`。**トークンは映さない**）。
5. 通し稽古を1回。ダッシュボードで「読み上げ」をオン、「判断」を「『見て』のときだけGemini」にして、「見て」を押す。

## 撮影のチェック

- [ ] 本体の再起動（落ちたとき）の直後は、「読み上げ」「判断」がオフに戻る。**戻ったら入れ直す**（既定はオフ）。
- [ ] 「判断」の表示に、Geminiへ送った回数（「送信N回」）が出る。「常にGemini」でも、自動の送信は**1分に1回まで**（無料枠の節約）。ボタンの「見て」は、いつでも使える。
- [ ] 「監視」は、顔を見つけると追従に切り替わり、見失って3秒後に、また首を振り始める。監視中は、首が動き続けるので、マイクの拍手反応は効かない（拍手の場面は、監視をオフにして撮る）。
- [ ] 手に持つ物（コップなど）と、背景がきれいなこと。他の人や、私的なものを映さない。
- [ ] Wi-Fiが安定している（ダッシュボードのRSSIが-40dBm前後）。
- [ ] 「見て」は、撮影のたびに数十秒あける。
- [ ] 撮影後、「判断」を「本体のみ」に戻し、「読み上げ」をオフにする。

## 言えること・言えないこと

言える（根拠あり）:
- 実機で、顔検出→挨拶→自分から質問→回答待ちの間も追従・相づち→回答の字幕、が動いた（ダッシュボードの記録、ログ、2026-10-30）。
- 実機で、「見て」（画像1枚→Gemini→状況の説明文→字幕と読み上げ）が動いた。応答時間は5〜15秒でばらつく。
- 通信の失敗（誤キー、到達不能、ハング）から、本体が回復した（`tools/fault_check.py`）。
- 追従制御の比較は、シミュレーションで、積分制御が定常誤差を除くことを示した。

言えない:
- 顔検出の精度が高い。自然さや愛着。待ち時間が短くなった（比較していない）。
- 安定して動き続ける。読み上げを有効にして質問を繰り返すと、本体が再起動することがある（原因未特定）。
- 音声の内容をAIが理解している（音量の大小だけ）。

## Gazebo/ROSについて

今回は使わない。Gazebo用のStack-chanのモデルがなく、環境の構築と検証が提出までの時間に収まらないため。代わりに、Pythonで閉ループの追従制御を計算した（`tools/track_sim.py`）。動画では、その図を見せる。ROS/Gazeboは、今後の課題。
