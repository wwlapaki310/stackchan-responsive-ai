# 追従制御のシミュレーション

**シミュレーションのみ。実機の測定ではない。** `tools/track_sim.py` が、ファームウェアの追従則(firmware/answer_demo)をPythonで再実装し、単純なモデルに対して閉ループで動かす。ロボット本体の性能、顔検出器の性能、サーボの実際の応答は測っていない。

```
python tools/track_sim.py --runs 60 --out docs/sim      # docs/sim/track_sim.csv と track_sim.png を出力
```

## モデルと仮定
- 人は世界角 `face(t)`、頭(カメラ)は `head(t)`。画像上の位置 `x = (face - head) / (FOV/2)`、`|x| < 1` のときだけ検出できる。
- カメラは16fps(実機のログで約16fps)。検出確率 p は1フレームあたり。実機の記録は、顔が前にある間に約4〜50%(条件を統制していない1人・1環境の記録)なので、p を 0.05〜0.9 で振る。
- **仮定(実機で未測定):** 視野角60°(50°、80°でも確認)、サーボの最大角速度90°/s(45、180°/sでも確認)、検出位置のノイズ σ=0.03。サーボの遅れ・バックラッシュ・電流制限は含まない。
- 制御則:
  - `prop`: 2026-10-27以前のファームウェア。ずれ x を ±15° の絶対角へ割り当てる。
  - `prop45`: 同じ則で範囲を ±45° に広げたもの(則と可動範囲の影響を分けるための比較対象)。
  - `int-G`: 現在のファームウェア。検出のたびに `yawTarget += int(smoothX * G)`(0.1°単位、不感帯0.08、±45°)。ファームウェアの設定は G=80。
- シナリオ: `step`(2秒後に+25°へ人が現れる)、`walk`(±30°を周期20秒で往復)、`reappear`(−20°にいて、8〜14秒は不在、その後+20°に再出現)。各設定60回、中央値と四分位範囲。

## 読み取れること(このモデルの中で)
- 比例則(`prop`、`prop45`)は、人が正面にいない位置で**定常偏差**が残る(`step`で約10°)。画像上のずれを絶対角に割り当てるため、頭が回って顔が中央に近づくとずれ x が小さくなり、目標角も戻るためである。可動範囲を広げても、偏差は残る。
- 積分則(`int-G`)は偏差を消せる。検出確率が低いほど収束に時間がかかり、ゲインを上げると速くなる。例: p=0.25、`step` で中心(±3°)に入る中央時間は G=40: 3.1秒、G=80: 1.2秒、G=160: 0.5秒。
- 順位(積分 > 比例、ゲインが高いほど速い)は、視野角50〜80°、サーボ速度45〜180°/sの範囲で変わらなかった(`track_sim.csv` の `fov`、`vmax`)。

## 読み取れないこと
- 実機で首が実際に顔を中央へ寄せる効果は、まだ測っていない(積分則の実機での効果は未検証)。
- G=160 はこのモデルでは最良だが、サーボの遅れを含まないため、実機で振動しない保証はない。ファームウェアの設定は G=80 のまま。
- 検出確率は一定と仮定している。実機では、顔の向き・照明・距離で変わる。
